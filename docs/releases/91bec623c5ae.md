# gewu-multiverse v0.1.23 — the twenty-third fix round

This is the twenty-fourth prebuilt release of `gewu-multiverse`. It is built from `main`
after the twenty-third round of interface fixes, and packed so you can try it without a
Rust toolchain. Nothing about the install or the design changed: if `v0.1.22` ran on
your machine, this one runs there too. The binary reports the version it is named
for: `gewu-multiverse --version` prints `0.1.23`.

## What it is

`gewu-multiverse` is a local, single-Universe Matrixverse — one small terminal
application that turns a Linux machine into a place where you run **agents against
your own Forgejo**, with no server, no accounts and no cloud. You install it, open
the terminal UI, point it at one Forgejo, and define each agent with its own model
endpoint, key and instructions. Agents run as children of the UI by default, or as
user units that outlive the window when you ask for that; every run leaves a log and
an append-only JSONL transcript. The README describes all of it, and the
[quickstart](https://github.com/Callo42/gewu-multiverse#quickstart-from-nothing-to-a-running-agent)
walks from install to a run's log.

### The twenty-third fix round — new in this build

The twenty-second round made the add-agent form submit where it says and point its
refusal at the field it names, gave every non-success reason a sentence on the landing
screen, and extended the consent record. This round finished the two places that round
left half-closed and closed four more that two independent walks found. Every wave was
closed by **enumeration** rather than by eye: every key the help, the legends and the
notes name was checked against the binding table; every overlay was listed with its
title, its body and whether its `more below; enlarge the window` declaration is true;
every surface that prints a run's reason was listed with how widely it applies; and every
sentence the product draws about a fact made on another machine or by another version was
checked against what is known, what is not, and what to do next. The new guards are
`tests/wave23-guards.rs`.

- **The add-agent form shows its refusal in the box it belongs to.** The reason was drawn
  in the status line only: the box's own error row sat below the last field, which is the
  row the window drops at the built geometry, while the cursor was moved up to the field
  the reason names. The reason is now drawn on the row immediately after the cursor's
  field and inside the window's pinned span, so the field and the sentence that names it
  are read together, and the box is sized to its content, so `more below; enlarge the
  window` is true when it is drawn.
- **One rule for a run's reason.** The hub drew an *unreadable* record's reason for the
  row — whether or not that agent was selected — but drew a `timed_out` or `stopped`
  reason only for the selected agent, so a list scan could not show why a row failed. One
  rule now governs every reason about an agent's run: it is drawn for that agent's row,
  naming the agent, whether or not the row is selected. Two agents with two outcomes show
  both reasons at once.
- **A key pressed where it is not bound names where it acts.** A written procedure can
  name a key on the wrong screen; the product's answer, `no key is bound to that — press ?
  for the list`, named no route. When the key is bound on another screen, the refusal now
  names that screen and what the key does there. Pressing `u` on the Agents screen
  answers *no key is bound to that on this screen — `u` sets the Forgejo instance address
  on the Forgejo screen (4); press ? for the list*, so the procedure can be corrected from
  the screen itself.
- **The review of an acknowledged record draws all its terms.** The read-only `R` review
  declared `more below; enlarge the window` but its body was a fixed height, so three of
  the eight terms bullets were unreachable at any window size. The box is now sized to its
  content (capped only by the window): at 120×45 all eight bullets are drawn and nothing
  is declared, and at the advertised 72×18 floor it declares its overflow on its own
  title.
- **The review is titled for the state it is in.** The read-only review kept the first-run
  heading `Before the first agent runs` even when a record existed and the acknowledgment
  was on file. The review is now titled `The terms you acknowledged — read-only`; the
  first-run heading and the digested terms text are unchanged, so the digest a record
  carries does not move.
- **A configuration moved to another machine says what to do.** When a `HOME` is copied to
  a second machine, the hub says the record was made on another machine and that this
  machine has not recorded a confirmation — but it named no way to record this machine's
  own, while `s` still started a run under the old record. The sentence now adds the
  consequence and the way back: `starting an agent here is still allowed under that
  record; to record this machine's own confirmation, remove <record path> and start
  again`.

### The twenty-second fix round — carried from v0.1.22

The twenty-first round gave the unreadable class its own sentence, agreed the hub and the
Runs screen while a run starts, made wide geometry honest and named the configuration a
sentence belongs to. This round fixed the seven findings two independent walks left. Two
rounds had already claimed the class the first two belong to — what the product says
about a file it did not write — so this round did not sweep screens: it **enumerated**
every site in the code that reads a path the product did not write and gave each site,
against each of six fates (missing, permission-denied, a directory, empty, non-UTF-8, a
valid file), the sentence it prints. The matrix is itself the guard
(`tests/foreign-file-matrix.rs`), shown failing on the base and passing now. The add-agent
form was made to submit where it says and to point its refusal at the field it names;
every non-success reason now reaches the landing screen; the consent record states plainly
what it can and cannot prove; the hub's unreadable reason follows the row; and an older
binary opened against a newer `HOME` now says so.

- **A file that is a directory is not a file with a size.** A `run.log` that was present
  but was a directory was drawn as a readable file with a size (`4.0 KiB`), and `o` then
  said it "is not there yet" — the word for a file that is absent. The file's fate is now
  decided by **opening** it, not by asking for its metadata: a directory answers
  `— the record could not be read: Is a directory (os error 21)`, a file the mode forbids
  reading answers `Permission denied (os error 13)`, and a size is drawn only for a
  regular, openable file. `o` and `T` print the same sentence the Agent screen does, so a
  transcript or a log that is a directory is never advertised at a normal size again.
- **An unreadable run record still shows the start it has.** The Runs `started (UTC)`
  column read `unknown start` for a present-but-unreadable record although the run id
  carries the instant the supervisor made it. The column now falls back to the run id
  before `unknown start`, and the Runs note leads with the read error the hub draws, so
  the row reads its real start clock together with `outcome: unreadable — the record
  could not be read: …`.
- **The add-agent form submits where it says, and a refusal points at its field.**
  `enter` submitted the form from any field, so a stray `enter` in a middle field could
  write an incomplete agent, and after a refusal the cursor stayed on the first field
  while the reason was drawn elsewhere — the next paste landed in the wrong place. Now
  `enter` moves on and writes only from the last field, `ctrl-s` writes from any field,
  and a refusal moves the cursor to the field its reason names and draws the reason
  there; the action line and the panel title name both keys.
- **Every non-success reason reaches the landing screen.** The hub named a run's reason
  only for `failed`; a `timed_out` or `stopped` run's reason lived only on the Runs
  screen. One rule now names the reason of every terminal non-success on the hub and in
  the Agent screen's `last run` field: `the last run of \`scribe\` did not go well: the
  run reached its timeout of 3 s and was stopped`.
- **The consent record says what it can and cannot prove.** The acknowledgment record is
  a plain TOML file with no signature, MAC or digest, and nothing said so. It now carries
  `terms_digest`, a SHA-256 of the terms text, and the product states the limit in the
  same words in the hub's note area and in the read-only review: the record is a plain,
  unsigned file that anyone who can read the directory can edit, and the digest only
  tells whether the terms text has changed since it was written — it is not proof that
  the product wrote it. The three digest answers (matches, differs, carries no digest)
  are each stated.
- **The unreadable reason follows the row, not the selection.** The hub drew the
  unreadable explanation only while the unreadable agent was selected, so an unselected
  row read `unreadable` with no reason anywhere. The reason now follows the row and names
  the agent, and a reload (`r`) cannot clear it while the state is held.
- **An older build against a newer configuration says so.** After an upgrade, running the
  older binary against the newer `HOME` said nothing about the mismatch. A `last-seen`
  record now carries the newest version that has opened the configuration (an older build
  never lowers it), and a build older than it draws `this configuration has been used by
  version X, which is newer than this build (Y); this build cannot know what that version
  wrote — run a build at least that new to read the configuration exactly`, while the
  acknowledgment line adds `used by version X since <date>`.

### The eighteenth fix round — carried from v0.1.18

The seventeenth round made a fact name its machine, a refusal replace its optimistic
status, and the class name the missing key. This round fixed what *walking the product
through a slow network, and through loss — a file deleted underneath a running UI, an
editor interrupted before it saved, a removed agent's records, a peer that dropped the

the endpoint test gave no sign it was running and let the previous result read as the new

the prefilled Forgejo address could not be cleared except by backspacing; and an editor

instead of by extending the finding's own screen: every read-then-write path in the code,
every bordered surface against the note area it owns, every result-bearing probe and its
stamp, every count and the rows it counts, and the four wording classes.

- **A result is never shown as current while it is stale, and a probe is never silent.**
  The endpoint test (`p`), the role check (`c`), the administrator role check (`C`) and the
  identity (`i`) ran on the UI thread and redrew only when they returned, so for the whole
  call the previous result was read as the new one and a slow endpoint looked like a hung

  `testing — started <age> (the result will replace this)` in the field and the footer says
  `testing the endpoint of \`<agent>\` on <machine> — the result follows`, the previous
  result is not drawn while the call is in flight, and the finished result replaces it when
  it lands. The role check and the administrator role check gained a persisted stamp
  (`role_checked_at_ms` + `role_check_machine`) drawn `— checked <age> on <machine>`, so a
  session view cannot read as current forever, joining the endpoint test's existing
  `tested_at_ms` + machine stamp.
- **A credentials file deleted under a running UI is put back in-session.** Every secret
  write began by *reading* the file, and the read mapped a `NotFound` straight to
  `cannot be created`, so deleting `credentials.toml` while the UI ran left every offered
  key refusing until a restart. The write path now treats an absent file as empty and
  creates it first through the product's own custody (mode `0600`, the template), so `k`,
  `f` and `A` put the file back in the same session. The Credentials screen says which
  state it is in — a file that is not there reads `the credentials file is not there yet —
  press k, f or A on this screen to write it`, not a creation failure for a directory that
  is writable.
- **Every overlay owns the note area behind it — one predicate, not a list.** The
  first-run acknowledgment modal stopped leaving a fragment behind in the sixteenth round
  by suppressing the note area under *that modal*; the class survived on the add-agent
  form, whose box left the tail `writes both files for you.` visible below it. The rule is
  now one predicate (`overlay_owns_screen()` = any overlay that owns the keys), and the two
  borderless note areas are not drawn at all while it holds and return whole when the
  overlay closes — so a new overlay cannot leave the fragment behind. The class is closed
  by a guard that draws every overlay over both note areas at 72×18, 80×24, 100×40 and
  120×40.
- **A removed agent's records are listed, not only counted.** After removing an agent the
  Runs screen counted its records in the footprint but the list omitted them, so their log
  and transcript could not be opened in the product. The list is now built from every agent
  directory on disk, so the count and the rows agree; a record whose agent the configuration
  no longer lists is listed like any other and carries `*` in the marker column, and the note
  says `N records belong to an agent the configuration no longer lists and are marked \`*\`
  in the list above`.
- **A dropped connection speaks in the product's words.** A peer that read the request and
  then closed was reported with the transport's own `io: Peer disconnected`. The product now
  maps it to `the request was sent, but the endpoint closed the connection` and strips any
  other leading `io: `, so no transport prefix reaches a screen; the run's log and transcript
  keep the transport's exact sentence as the audit trail.
- **A prefilled field can be cleared with one key, and an interrupted editor states its
  recovery.** The Forgejo address prompt (`u`) is prefilled with the address in force and
  could be cleared only by backspacing; `ctrl-u` now clears it (and the secret prompt and the
  add-agent form), handled in one place and named on each answer line. And an editor killed
  before it saved returned with `code None` and no recovery sentence; the interrupted return
  now reads `<program> was interrupted — it may not have been saved`, names the
  emergency-save file when one is there (`an earlier edit was not saved and the editor kept
  it in … — open that file to recover`), and ends `the keys are the product's again`.

  clear **every** status on any screen change, so a status added later cannot join a
  stale family by mistake. What must persist across screens is drawn from the state that
  owns it — the note areas read the records, the acknowledgment line reads the record —
  never from the status line.
- **A list or a count that stops at fifty says so.** The Runs list holds the newest fifty
  of the run records on disk, and the footer's finished count was computed from that same
  fifty, so with sixty or two thousand records the screen said `of 50` and the footer said
  `50` with nothing to say the history was longer. The Runs note area now says how many
  older records are not listed, and the footer count gains a `+` (`· 50+ finished`) when
  the newest fifty all finished since the UI started and older records exist. The cap is
  on the list, not on the records, and the screen says which one it is.
- **The record footprint and the cleanup expectation are on the screen.** Run records
  accumulate with every run, and nothing said how many there were, how much room they took,
  or what a person should do about them; a record whose agent had been removed vanished
  from the screen but stayed on disk. The Runs note area now draws `N run records on disk,
  <size> in total.`, then, when some belong to an agent the configuration no longer lists,
  how many and that they stay on disk until they are deleted, then `To free their space,
  remove a run's directory under that path. The product only reads run records; it never
  deletes one by itself.` The footprint counts every agent directory, configured or not, so
  a removed agent's history does not disappear from the count.
- **The files that grow with each run show their size.** The Agent screen's `newest log`
  reads its size beside the path and gains a `transcript` field with its own size, and the
  Runs note repeats both sizes beside their paths, so the files a run appends to are
  visibly growing instead of being a bare path.
- **The risk acknowledgment is visible to a second person.** On a configuration directory
  that already holds a recorded acknowledgment, the hub's note area now names when it was
  given and the version the record itself carries, and `R` reads the terms again
  **read-only**, so reading them does not rewrite the record. A second person on a used
  machine can see what someone else agreed to, before anything starts.
- **The identity sentence and the failure class are whole words.** The Forgejo identity
  line now finishes — `not settled — press i for \`gewu-scribe\`; v supplies the token` —
  rather than stopping at `… the token is from v`. The hub's state column shortens every
  failure class to a word that fits whole (`failed (server)`, `failed (key)`), never an
  ellipsised fragment such as `failed (s…er_error)`; the Agent screen keeps the long form
  (`failed (server_error)`) where the column is wide enough.
- **A leftover secret carries an age.** A credential left behind by an agent that is no
  longer configured now reads with the age of the file that holds it
  (`left by a credentials file last written 3 days ago`), so a stale secret can be told
  from one just written.

### The ninth fix round — carried from v0.1.9

The eighth round made the scroll answer truthful and the refusal speak in the product's

configuration field* revealed: `^C` inside a hand-off killed the whole product and stopped
work in flight without asking; the Agent screen showed an `instruction` path the run
silently ignored; a run's missing key reached the screens as a file name and a TOML

## What it needs

- A 64-bit **x86_64** Linux machine with **glibc 2.39 or newer** — Ubuntu 24.04 or newer,
  Debian 13 or newer, Fedora 40 or newer, or any distribution that new. The binary is
  dynamically linked against your system's glibc; it is not a static build. The floor was
  read from the ELF (`.gnu.version_r` names `GLIBC_2.39`), not assumed.
- A **terminal**. The UI needs a terminal on standard input and standard output; started
  without one it stops with a sentence rather than a panic.
- **Your own `git`**, when you ask an agent to work on a repository.
- At **first run**, nothing beyond the above: the tool writes a commented `config.toml`
  and a `credentials.toml` (mode 0600) under `~/.config/gewu-multiverse`, and asks you
  once to acknowledge that a run acts with your rights and is not a sandbox. Press `y`
  to record it, or `n` to leave it; a start stays refused until it is recorded. On a
  directory where it was already recorded, the hub names when and under which version,
  and `R` reads the terms again without changing the record.

## What it deliberately does not do yet

- **No build for other machines.** This is x86_64 Linux only: there is no aarch64 build,
  no musl/static build, and no macOS or Windows build. On a machine with an older glibc
  than 2.39, use the source install instead.
- **No package format.** The release is a tarball, a checksum and this note: there is no
  `.deb`, no `.rpm`, no container image. The repository's `install.sh` performs the
  download, checksum and install in one line.
- **No service.** The terminal UI is the interface. An agent can be put under your own
  user systemd from the UI — that is documented — but nothing is installed as a service.
- **No sandbox.** An agent runs as you. That is a layout, not a security boundary, and
  the README says so at length.
- **The product never deletes a run record.** Run records and their logs and transcripts
  accumulate; the Runs screen now says how many there are, how much room they take, and
  that freeing the space is a person removing a run's directory. Automatic pruning is
  deliberately not done.
- **The crate version string is `0.1.23`, and it matches the tag.** `Cargo.toml` and the
  committed `Cargo.lock` both carry it, so `gewu-multiverse --version` reports the version
  the release is named for, and `cargo build --locked` means something on a fresh clone.

## How it was built

`cargo build --release --locked` on x86_64 Linux, with rustc 1.98.1 and cargo 1.98.1,
target `x86_64-unknown-linux-gnu`, at revision
`91bec623c5aeb537a0e9994c816638e5081ae1b4` (the version commit on the release branch).
The repository commits its `Cargo.lock`, so the build held `--locked` against the
committed lock. The tarball also holds the README and both licence files.
