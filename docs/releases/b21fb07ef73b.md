# gewu-multiverse v0.1.3 — the third fix round

This is the fourth prebuilt release of `gewu-multiverse`. It is built from `main`
after the third round of interface fixes, and packed so you can try it without a
Rust toolchain. Nothing about the install or the design changed: if `v0.1.2` ran on
your machine, this one runs there too. As with `v0.1.2`, the binary reports the
version it is named for: `gewu-multiverse --version` prints `0.1.3`.

## What it is

`gewu-multiverse` is a local, single-Universe Matrixverse — one small terminal
application that turns a Linux machine into a place where you run **agents against
your own Forgejo**, with no server, no accounts and no cloud. You install it, open
the terminal UI, point it at one Forgejo, and define each agent with its own model
endpoint, key and instructions. Agents run as children of the UI by default, or as
user units that outlive the window when you ask for that; every run leaves a log and
an append-only JSONL transcript. The README describes all of it, and the
[quickstart](https://github.com/Callo42/gewu-multiverse#quickstart-from-nothing-to-a-running-agent)
walks from install to a run's log.

## What changed since v0.1.2

The second fix round made running an agent honest: a killed window left no run
behind, secrets and removal lived in the product, and the smaller interface wrongs
were closed. This round fixes what *watching several agents over time* revealed:
a list that hid what did not fit, a hub that forgot what had happened, and a set of
smaller truths that were not on screen. Each of these has a test behind it.

- **The agent list no longer hides an agent.** When more agents are configured than
  fit, the list shows a window of rows titled `agents a–b of N — ↓/↑ more`; the
  selected row is always drawn, so the selection never moves onto a row you cannot
  see. The advertised minimum (72×18) now draws a real agent row, and one size below
  says the window is too small instead of clipping in silence.
- **The selected row carries a `>` in text**, on the Agents and Runs lists, not only
  in colour.
- **A restart remembers.** A window opened after a run has ended seeds each agent
  from its newest terminal record, so the hub shows `stopped`, `exited 0` or
  `failed (class)` — not `idle` — and the last reason is kept.
- **A run in flight is visible everywhere.** The footer carries `Running: N of M`
  on every screen and appends `· K finished` once a run has ended since the window
  opened; the Runs screen shows `running (elapsed)` rather than an open-ended
  `running`.
- **A signalled stop reads truthfully.** Once the run's record is closed the status
  says `stopped … its process group was signalled and is proven gone`, in the past
  tense, so it agrees with the row.
- **The removal confirmation only promises files that exist.** If the agent has no
  files under its directory yet, the confirmation says so, and the removal status
  agrees.
- **The Forgejo screen says which identity will act.** The agent identity and its
  mode (`managed` or `supplied`) are shown persistently; a failed clone names the
  account it acted as and says the repository list came from the role token; and the
  add-agent form calls its field the **role** token, with the agent's own token named
  as separate.
- **The Runs note area leads with the reason a run ended**, so the reason is not the
  line that wraps off the bottom.
- **An interrupted editor is not a loss.** The Instruction screen names the
  emergency save an editor left behind, and an instruction file that holds only the
  template's placeholder reads as the empty state, with the reason.
- **A credential for a removed agent is marked** as belonging to no configured
  agent; nothing is deleted quietly.
- **The smaller wrongs, each with a test.** The hub seeds from the newest record;
  the Runs selection carries `>`; a run's elapsed time comes from its own record;
  and the footer counts what finished since the window opened.

## What it needs

- A 64-bit **x86_64** Linux machine with **glibc 2.39 or newer** — Ubuntu 24.04 or newer,
  Debian 13 or newer, Fedora 40 or newer, or any distribution that new. The binary is
  dynamically linked against your system's glibc; it is not a static build. The floor was
  read from the ELF (`.gnu.version_r` names `GLIBC_2.39`), not assumed.
- A **terminal**. The UI needs a terminal on standard input and standard output; started
  without one it stops with a sentence rather than a panic.
- **Your own `git`**, when you ask an agent to work on a repository.
- At **first run**, nothing beyond the above: the tool writes a commented `config.toml`
  and a `credentials.toml` (mode 0600) under `~/.config/gewu-multiverse`, and asks you
  once to acknowledge that a run acts with your rights and is not a sandbox. Press `y`
  to record it, or `n` to leave it; a start stays refused until it is recorded.

## What it deliberately does not do yet

- **No build for other machines.** This is x86_64 Linux only: there is no aarch64 build,
  no musl/static build, and no macOS or Windows build. On a machine with an older glibc
  than 2.39, use the source install instead.
- **No package format.** The release is a tarball, a checksum and this note: there is no
  `.deb`, no `.rpm`, no container image. The repository's `install.sh` performs the
  download, checksum and install in one line.
- **No service.** The terminal UI is the interface. An agent can be put under your own
  user systemd from the UI — that is documented — but nothing is installed as a service.
- **No sandbox.** An agent runs as you. That is a layout, not a security boundary, and
  the README says so at length.
- **The crate version string is `0.1.3`, and it matches the tag.** `Cargo.toml` and the
  committed `Cargo.lock` both carry it, so `gewu-multiverse --version` reports the version
  the release is named for, and `cargo build --locked` means something on a fresh clone.

## How it was built

`cargo build --release --locked` on x86_64 Linux, with rustc 1.98.1 and cargo 1.98.1,
target `x86_64-unknown-linux-gnu`, at revision
`b21fb07ef73b89b5187a05cc4837da7b85bc4a78`. The repository commits its `Cargo.lock`,
so the build held `--locked` against the committed lock. The tarball also holds the
README and both licence files.
