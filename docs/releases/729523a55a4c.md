# gewu-multiverse v0.1.10 — the tenth fix round

This is the eleventh prebuilt release of `gewu-multiverse`. It is built from `main`
after the tenth round of interface fixes, and packed so you can try it without a
Rust toolchain. Nothing about the install or the design changed: if `v0.1.9` ran on
your machine, this one runs there too. The binary reports the version it is named
for: `gewu-multiverse --version` prints `0.1.10`.

## What it is

`gewu-multiverse` is a local, single-Universe Matrixverse — one small terminal
application that turns a Linux machine into a place where you run **agents against
your own Forgejo**, with no server, no accounts and no cloud. You install it, open
the terminal UI, point it at one Forgejo, and define each agent with its own model
endpoint, key and instructions. Agents run as children of the UI by default, or as
user units that outlive the window when you ask for that; every run leaves a log and
an append-only JSONL transcript. The README describes all of it, and the
[quickstart](https://github.com/Callo42/gewu-multiverse#quickstart-from-nothing-to-a-running-agent)
walks from install to a run's log.

## What changed since v0.1.2

If you are upgrading from `v0.1.2`, this build carries **eight** rounds of fixes: the
third fix round, which `v0.1.3` published; the fourth, which `v0.1.4` published; the
fifth, which `v0.1.5` published; the sixth, which `v0.1.6` published; the seventh,
which `v0.1.7` published; the eighth, which `v0.1.8` published; the ninth, which
`v0.1.9` published; and the tenth fix round, which is this build. If you are already
on `v0.1.9`, the new work is the tenth round, listed first; the earlier rounds are
summarised after it, so a `v0.1.2` reader loses nothing.

### The tenth fix round — new in this build

The ninth round fixed what answering the product's own exit and its own configuration
field revealed, and it cleared the scroll sentence wherever the screen changed. This
round fixed what *watching the product over a long sitting with a real history* revealed:
every other status sentence still outlived the screen that made it; the record list and
the footer count both stopped at fifty and presented fifty as the whole history; nothing
anywhere said how many run records were on disk, how much room they took, or what a
person was expected to do about them; the files that grow with every run showed no size;
a used configuration gave the second person no record of the risk acknowledgment and no
way to read the terms; the Forgejo identity sentence stopped mid-word; and the hub's
failure class was ellipsised rather than shown as a word that fits whole. Each fix has a
test behind it, and the classes were swept: the status line, the counted and listed
surfaces, and the surfaces where something the product leaves on disk accumulates.

- **Every status sentence dies with the screen that made it.** The ninth round cleared
  the panel-scroll sentence on a screen change, written as a list of the sentences that
  belonged to that one family; every other status — an unbound-key sentence, `risk
  acknowledged and recorded in …` — survived the change and said something untrue on the
  new screen. The rule is now the mechanism instead of a list: `show` and `shift_screen`
  clear **every** status on any screen change, so a status added later cannot join a
  stale family by mistake. What must persist across screens is drawn from the state that
  owns it — the note areas read the records, the acknowledgment line reads the record —
  never from the status line.
- **A list or a count that stops at fifty says so.** The Runs list holds the newest fifty
  of the run records on disk, and the footer's finished count was computed from that same
  fifty, so with sixty or two thousand records the screen said `of 50` and the footer said
  `50` with nothing to say the history was longer. The Runs note area now says how many
  older records are not listed, and the footer count gains a `+` (`· 50+ finished`) when
  the newest fifty all finished since the UI started and older records exist. The cap is
  on the list, not on the records, and the screen says which one it is.
- **The record footprint and the cleanup expectation are on the screen.** Run records
  accumulate with every run, and nothing said how many there were, how much room they took,
  or what a person should do about them; a record whose agent had been removed vanished
  from the screen but stayed on disk. The Runs note area now draws `N run records on disk,
  <size> in total.`, then, when some belong to an agent the configuration no longer lists,
  how many and that they stay on disk until they are deleted, then `To free their space,
  remove a run's directory under that path. The product only reads run records; it never
  deletes one by itself.` The footprint counts every agent directory, configured or not, so
  a removed agent's history does not disappear from the count.
- **The files that grow with each run show their size.** The Agent screen's `newest log`
  reads its size beside the path and gains a `transcript` field with its own size, and the
  Runs note repeats both sizes beside their paths, so the files a run appends to are
  visibly growing instead of being a bare path.
- **The risk acknowledgment is visible to a second person.** On a configuration directory
  that already holds a recorded acknowledgment, the hub's note area now names when it was
  given and the version the record itself carries, and `R` reads the terms again
  **read-only**, so reading them does not rewrite the record. A second person on a used
  machine can see what someone else agreed to, before anything starts.
- **The identity sentence and the failure class are whole words.** The Forgejo identity
  line now finishes — `not settled — press i for \`gewu-scribe\`; v supplies the token` —
  rather than stopping at `… the token is from v`. The hub's state column shortens every
  failure class to a word that fits whole (`failed (server)`, `failed (key)`), never an
  ellipsised fragment such as `failed (s…er_error)`; the Agent screen keeps the long form
  (`failed (server_error)`) where the column is wide enough.
- **A leftover secret carries an age.** A credential left behind by an agent that is no
  longer configured now reads with the age of the file that holds it
  (`left by a credentials file last written 3 days ago`), so a stale secret can be told
  from one just written.

### The ninth fix round — carried from v0.1.9

The eighth round made the scroll answer truthful and the refusal speak in the product's
own words. This round fixed what *answering the product's own exit and its own
configuration field* revealed: `^C` inside a hand-off killed the whole product and stopped
work in flight without asking; the Agent screen showed an `instruction` path the run
silently ignored; a run's missing key reached the screens as a file name and a TOML
section; a legal 32-character name was clipped into its neighbour; and a scroll sentence
outlived the screen that made it. Each fix has a test behind it, and the
name/state-clipping class was swept per column and per screen.

- **A hand-off's own exit returns to the product.** The signal is caught for the product
  only while the user's program has the terminal — with a real handler, never `SIG_IGN`,
  which the child would inherit across `exec` — and the child keeps its own `^C`. On
  return, a caught `SIGINT` takes the same ask-before-leaving path the UI's own `q` and
  `^C` take: one warning that names the runs, then a stop only on a second chord.
- **The configured instruction path is the one every screen and the run read.** A
  hand-written non-default `instruction` path now moves the file the Agent screen shows,
  the Instruction screen reads, the `e` editor writes and the run plan carries, so the path
  the user reads is the document the run actually sends.
- **A run's missing key reads in the product's own words on every surface a person acts
  from** — `the model key for \`<agent>\` is gone — press 5 and then k on the Credentials
  screen to add one` — while the run's own log and transcript keep the file's exact
  sentence, which is the audit trail.
- **A legal name is never clipped into an ambiguous neighbour.** A column that shows an
  agent's name is widened to the shortest width that keeps every configured name distinct;
  only when the window cannot hold that width is the name shortened with an ellipsis that
  keeps both ends, so names that differ at either end stay distinct.
- **`q` is one thing per place, and never the destructive one.** In the removal and
  leftover-secret confirmations `q` now **keeps**, like `n` and `esc`, and the footer's
  legend under an overlay reads `esc closes this overlay` instead of advertising a quit
  that is not bound there.
- **The smaller truths.** The pager sentence names `esc`'s trap; the "any other key to
  stay" answer is consumed; and the declined-acknowledgment sentence keeps its object.

### The eighth fix round — carried from v0.1.8

The seventh round made every panel and note area scroll, and gave a scrolled surface
its `↑ more above` marker. This round fixed what *reading that answer on the machine
the user actually installed it on* revealed: the scroll offset was shared across
screens, the marker was computed only for the unscrolled state, Forgejo below the
advertised floor declared content it could not reach, a missing key was refused by
naming a file and a TOML section instead of the product's own key, the tab bar
clipped its last name at the floor, and the Credentials legend did not offer the
delete it showed the need for.

- **The scroll offset belongs to the screen it was made on** — every way of changing
  screens returns the new screen to its own top.
- **A scrolled surface never hides its own top in silence**, and the markers are true at
  every offset, not only at offset zero.
- **Below the advertised floor, Forgejo scrolls**, so the below-fold content is reached
  rather than merely declared.
- **A refusal names the product's own key, not a file**: `press 5 and then k on the
  Credentials screen to add one`; the run's own log keeps the file's exact sentence.
- **The tab bar keeps every name at the advertised floor.**
- **The legend offers the delete it shows the need for.**

### The seventh fix round — carried from v0.1.7

## What it needs

- A 64-bit **x86_64** Linux machine with **glibc 2.39 or newer** — Ubuntu 24.04 or newer,
  Debian 13 or newer, Fedora 40 or newer, or any distribution that new. The binary is
  dynamically linked against your system's glibc; it is not a static build. The floor was
  read from the ELF (`.gnu.version_r` names `GLIBC_2.39`), not assumed.
- A **terminal**. The UI needs a terminal on standard input and standard output; started
  without one it stops with a sentence rather than a panic.
- **Your own `git`**, when you ask an agent to work on a repository.
- At **first run**, nothing beyond the above: the tool writes a commented `config.toml`
  and a `credentials.toml` (mode 0600) under `~/.config/gewu-multiverse`, and asks you
  once to acknowledge that a run acts with your rights and is not a sandbox. Press `y`
  to record it, or `n` to leave it; a start stays refused until it is recorded. On a
  directory where it was already recorded, the hub names when and under which version,
  and `R` reads the terms again without changing the record.

## What it deliberately does not do yet

- **No build for other machines.** This is x86_64 Linux only: there is no aarch64 build,
  no musl/static build, and no macOS or Windows build. On a machine with an older glibc
  than 2.39, use the source install instead.
- **No package format.** The release is a tarball, a checksum and this note: there is no
  `.deb`, no `.rpm`, no container image. The repository's `install.sh` performs the
  download, checksum and install in one line.
- **No service.** The terminal UI is the interface. An agent can be put under your own
  user systemd from the UI — that is documented — but nothing is installed as a service.
- **No sandbox.** An agent runs as you. That is a layout, not a security boundary, and
  the README says so at length.
- **The product never deletes a run record.** Run records and their logs and transcripts
  accumulate; the Runs screen now says how many there are, how much room they take, and
  that freeing the space is a person removing a run's directory. Automatic pruning is
  deliberately not done.
- **The crate version string is `0.1.10`, and it matches the tag.** `Cargo.toml` and the
  committed `Cargo.lock` both carry it, so `gewu-multiverse --version` reports the version
  the release is named for, and `cargo build --locked` means something on a fresh clone.

## How it was built

`cargo build --release --locked` on x86_64 Linux, with rustc 1.98.1 and cargo 1.98.1,
target `x86_64-unknown-linux-gnu`, at revision
`729523a55a4c58393752345901e7607f12631c51` (the version commit on the release branch).
The repository commits its `Cargo.lock`, so the build held `--locked` against the
committed lock. The tarball also holds the README and both licence files.
