# gewu-multiverse v0.1.13 — the thirteenth fix round

This is the fourteenth prebuilt release of `gewu-multiverse`. It is built from `main`
after the thirteenth round of interface fixes, and packed so you can try it without a
Rust toolchain. Nothing about the install or the design changed: if `v0.1.12` ran on
your machine, this one runs there too. The binary reports the version it is named
for: `gewu-multiverse --version` prints `0.1.13`.

## What it is

`gewu-multiverse` is a local, single-Universe Matrixverse — one small terminal
application that turns a Linux machine into a place where you run **agents against
your own Forgejo**, with no server, no accounts and no cloud. You install it, open
the terminal UI, point it at one Forgejo, and define each agent with its own model
endpoint, key and instructions. Agents run as children of the UI by default, or as
user units that outlive the window when you ask for that; every run leaves a log and
an append-only JSONL transcript. The README describes all of it, and the
[quickstart](https://github.com/Callo42/gewu-multiverse#quickstart-from-nothing-to-a-running-agent)
walks from install to a run's log.

### The thirteenth fix round — new in this build

The twelfth round made a paste a paste, made the advice true under every overlay and
for both editor keys, named every hand-off program's own state location, said where
the binary lives and that removing it is the whole uninstall, marked a moved
configuration's dead path and named the live one, read a workspace with history as
history, and drew the identity report once and whole at 80×24. This round fixed what
*walking the tree the product leaves behind, and reading what it says about a
repository whose agent has no recorded identity,* revealed: the directories the
product created were only private at the last component — `agents/`, the state root,
each agent, run and skill directory were made with the process umask and sat at
`0775` while the directories inside them were `0700` — and the configuration file was
written `0664` beside a credentials file that was already `0600`. Each fix has a test
behind it, and both classes were swept by enumeration: every directory the product
creates, from the configuration root to a run's own copied skills, and every sentence
built from a comparison against state that may be empty.

- **One custody for everything the product writes.** Every directory the product
  creates under its configuration and state roots is now held to mode `0700` — the
  configuration root, `agents/` and each agent, skill and workspace directory, and the
  state root with each agent, run and run-skills directory — and every file it writes
  is `0600`: the configuration file, the credentials file, the acknowledgment record,
  the instruction, steps and skill templates, the plan, the log and the transcript.
  The one exception is the `systemd` unit, `0644` because it names paths and holds no
  secret, inside a `0700` directory. The Credentials screen states the credentials
  file's real mode and the same custody for the files beside it.
- **The workspace sentence is honest about an unrecorded identity.** The Agent
  screen's `repository` field compared the repository's local git identity against an
  identity built from whatever was recorded — with nothing recorded, against the empty
  string `" <>"` — and so declared `not the agent's` when the product had nothing to
  compare with. When no Forgejo identity is recorded for the agent yet, the sentence
  now names that state and says the product cannot tell whether the git identity is
  the agent's, and points at `i` to settle one; a recorded identity that matches still
  reads `the agent's` and one that differs still reads `not the agent's`. An empty
  login, email or mode now reads as absent on the identity lines too, so the `identity`
  field says `not settled` rather than drawing an empty account.

### The twelfth fix round — carried from v0.1.12

The eleventh round made every claim match the deed: a hand-off reported created,
edited or not changed and wrote only at the hand-off; a destination that already
held a repository was reported as kept; one fact got one number; the identity named
its agent and aged; both acknowledgment versions were labelled; a path broke at its
separators; and the pager handed the `HOME` back as it found it. This round fixed
what *installing the release and reading it the way a person does* revealed: a paste
at a screen with no field open was answered, but a paste under an overlay that owned
the keys was dropped in silence (and the one generic sentence was wrong under four
more overlays); the editor overlay's `N` advice contradicted nano, which leaves at
once on an unmodified buffer; the hand-back still left `~/.local/share/nano`; nothing
said where the binary lived or that removing it is the whole uninstall; a
configuration that had moved drew a run record's dead path as if it were today's; a
workspace that held a repository was only ever a path; and at 80×24 the identity
report was drawn twice and clipped mid-sentence. Each fix has a test behind it, and
the classes were swept: every input surface against every paste path, every advice
surface, every program a hand-off spawns, every surface that draws a record's reason,
every workspace surface, every panel and note area at 80×24, and every age string.

- **A paste is a paste, and an overlay answers for itself.** A bracketed paste at a
  screen with no field open is dropped with a sentence naming where it can land
  (`press n for the form, or k/f/v/A for a secret`), and a paste into a one-line
  field keeps its first line, names the rest as unused and **replaces** the field.
  Under an overlay that owns the keys the sentence now says what owns the screen
  instead of offering keys that would not work: `answer this screen first: y to
  acknowledge, or n for not now` at the first-run acknowledgment, and each
  confirmation (removal, leftover-secret delete, leave question) names its own
  answer. A raw byte stream the terminal does not frame as a paste is
  indistinguishable from typing, and the product is not asked to answer for it.
- **The editor advice is true whether or not the editor asks.** The no-`$EDITOR`
  overlay said `press Y and enter to save, or N to leave without saving`; nano with
  an unmodified buffer leaves at `^X` at once and never asks, so the person's `N`
  reached the product and opened the add-agent form. It now reads `In nano: ^X
  leaves; if it asks, Y and enter saves and N does not.`
- **The verb agrees with its subject.** The overlay said `the declared steps of
  \`scribe\` opens in:`; the verb now comes from the label, so plural labels take
  `open` and singular labels `opens`, and the same rule replaced the string test in
  the edit statuses.
- **Every program a hand-off spawns gets a state location of its own.** `nano` gets
  an `$XDG_DATA_HOME` in a scratch directory that is removed when it exits (so no
  `~/.local/share/nano`), `vi`/`vim`/`nvim`/`ex` get `-i NONE` (so no `~/.viminfo`),
  and `less` keeps its history at `/dev/null`; a program the person chose with
  `$EDITOR`/`$VISUAL`/`$PAGER` that the product does not know keeps its own files
  and is named before it takes the screen. A run of `t`, `K`, `o` and a quit now
  leaves only the product's own named files.
- **`--help` names the binary and its uninstall.** The closing line reads `This
  program is one file — <the running binary> — and removing it is the whole
  uninstall. The configuration and state directories above are left as they are.`
  It is true of a release in `~/.local/bin`, of any `$INSTALL_DIR`, and of a build
  you ran yourself. No `--uninstall` flag was added: the uninstall really is one
  file.
- **A moved configuration names what is missing.** A run record's stored sentence
  embeds the absolute instruction path of the run's own time. When that path is not
  the agent's live instruction, the drawn sentence marks it — `(the path \`<old>\` is
  from when that run ran; the instruction now is <live>)` — and claims nothing about
  whether the complaint still holds.
- **A workspace with history is read, not only pathed.** The Agent screen gains a
  `repository` field read from the repository itself: the branch, the short commit
  and its age, whether the tree is clean or how many paths changed, and whose local
  git identity its commits carry. What the product cannot read is said plainly.
- **The identity report is drawn once and never clipped.** At 80×24 the report
  appeared twice (in the panel and again in the status line) and was cut mid-sentence.
  It is now drawn once on the Forgejo panel, the status after `i` is a one-line
  receipt, and a bordered panel never draws half a wrapped line — whole logical lines
  are dropped from the bottom and `]` reaches the rest.
- **The hand-off statuses name their file, and the first-run modal stops declaring
  hidden overflow.** Every created, edited or unchanged status names `steps.txt`,
  `SKILL.md` or `instruction.md`; and the note area draws no overflow declaration
  while the acknowledgment modal owns the screen, because it would point at rows the
  modal hides.
- **One age ladder.** `1 minute ago` was the first step after `just now`; the ladder
  now has a seconds rung — `just now` (0–9 s), `N seconds ago` (10–59 s), then
  minutes, hours and days — and every age site uses it.

### The eleventh fix round — carried from v0.1.11

The tenth round made every status die with its screen, named the record cap and the
record footprint, and put a size beside every growing file. This round fixed what
*checking each claim the product makes against what it actually did* revealed: two
hand-off keys created a file at the keypress and then reported "not changed"; a clone
onto a directory that already held a repository said "is ready" without saying it had
kept what was there; one Runs screen showed two different totals under the words "on
disk" while the footprint printed logical bytes and `du` reported about four times
that; the identity appeared in three shapes on three surfaces and its report was
session-only, its `(created now)` never aging; the acknowledgment named the
predecessor's version while no screen showed the version now running; a record path at
the floor wrapped inside a file name; a pager hand-off dropped a `.lesshst` history
file into the person's `HOME`; and a secret-in-config refusal named a section the way
the parser holds it rather than the way the file writes it. Each fix has a test behind
it, and the classes were swept: every hand-off key, every action that claims a state,
every surface that prints a total, and every surface that shows an identity.

- **A hand-off reports what it actually did.** `e`, `t` and `K` used to create the
  instruction, the steps file or the new skill **at the keypress**, before the editor
  ran, and then report `not changed` — so a person who cancelled the `no $EDITOR`
  confirmation was left with a file the status said did not change. The file is now
  written only at the hand-off itself, and the status distinguishes **created**,
  **edited** and **not changed**: an untouched new steps file reads `the declared steps
  of \`scribe\` did not exist; the template was created and left unchanged (true) — it
  declares 0 shell steps, so the screen now shows the file`, and backing out of the
  confirmation creates nothing at all.
- **A destination that already holds a repository is reported as kept.** `g` on a
  path that was already a git repository said `… is ready in …`, having neither cloned
  nor fetched and having quietly rewritten the repository's local git identity. It now
  returns two distinct sentences — the clone says it cloned, the reuse says
  `… was already a git repository at <path> — kept, not cloned or fetched; its local
  git identity was set to <identity>` — and a non-git non-empty directory is still
  refused.
- **One fact gets one number, and the definition is named.** The Runs screen showed
  `120 run records on disk, 81.2 KB in total.` beside `… of 110 on disk`, and the size
  was the sum of file lengths while `du` reported the allocated ~4×. A size is now the
  sum of **file bytes**, the one definition every size in the product already used
  (instructions, logs, transcripts, skills), and the footprint says so: `N run records
  on disk, <size> of file bytes in total.` The cap clause names each population — the
  configured count, the unlisted count and the total are distinct — so `older records
  are not listed` counts every unlisted record, including those of an agent the
  configuration no longer lists.
- **The identity names its agent and ages.** The `agent identity` field now names the
  agent — `<login> <email> as \`<agent>\` (<mode>)` — on every surface that shows an
  identity, the "not settled" sibling names it too, and the fuller report is drawn
  whenever the identity is settled and the role check has run, including in a later
  session. The creation time is stored with the identity, so `(created now)` becomes
  `(created 3 minutes ago)` after a restart instead of never aging.
- **Both versions are labelled in the acknowledgment.** The record line named only the
  predecessor's version, so a second person could not compare. It now reads `the risk
  was acknowledged on <date> (version <theirs>; this build is <ours>)`, and `R` still
  reads the terms again without changing the record.
- **A path breaks at its separators, not inside a file name.** At the advertised
  80-column floor a long record path wrapped mid-file-name (`…-0059/r` then `un.log`).
  A path now carries a zero-width break opportunity after each `/`, so it is unchanged
  when it fits and breaks between directories when it does not, and the file name stays
  whole.
- **The pager hands the `HOME` back as it found it.** Opening a log in `less` wrote a
  `.lesshst` search history into the person's `HOME`; the pager now runs with its
  history disabled, and `nano` is asked not to write its own search history either. A
  control run of the same pager without the product's environment still writes the file,
  which is what the fix stops.
- **A refusal names the section the way the file writes it.** A secret-like key in the
  configuration was refused under `the top level.forgejo`; it now reads `under
  \`[forgejo]\`` (and `\`[[agents]]\`` for an array element, `the top level` for a root
  key), so the person can find the line.

### The tenth fix round — carried from v0.1.10

The ninth round fixed what answering the product's own exit and its own configuration
field revealed, and it cleared the scroll sentence wherever the screen changed. This
round fixed what *watching the product over a long sitting with a real history* revealed:
every other status sentence still outlived the screen that made it; the record list and
the footer count both stopped at fifty and presented fifty as the whole history; nothing
anywhere said how many run records were on disk, how much room they took, or what a
person was expected to do about them; the files that grow with every run showed no size;
a used configuration gave the second person no record of the risk acknowledgment and no
way to read the terms; the Forgejo identity sentence stopped mid-word; and the hub's
failure class was ellipsised rather than shown as a word that fits whole. Each fix has a
test behind it, and the classes were swept: the status line, the counted and listed
surfaces, and the surfaces where something the product leaves on disk accumulates.

- **Every status sentence dies with the screen that made it.** The ninth round cleared
  the panel-scroll sentence on a screen change, written as a list of the sentences that
  belonged to that one family; every other status — an unbound-key sentence, `risk
  acknowledged and recorded in …` — survived the change and said something untrue on the
  new screen. The rule is now the mechanism instead of a list: `show` and `shift_screen`
  clear **every** status on any screen change, so a status added later cannot join a
  stale family by mistake. What must persist across screens is drawn from the state that
  owns it — the note areas read the records, the acknowledgment line reads the record —
  never from the status line.
- **A list or a count that stops at fifty says so.** The Runs list holds the newest fifty
  of the run records on disk, and the footer's finished count was computed from that same
  fifty, so with sixty or two thousand records the screen said `of 50` and the footer said
  `50` with nothing to say the history was longer. The Runs note area now says how many
  older records are not listed, and the footer count gains a `+` (`· 50+ finished`) when
  the newest fifty all finished since the UI started and older records exist. The cap is
  on the list, not on the records, and the screen says which one it is.
- **The record footprint and the cleanup expectation are on the screen.** Run records
  accumulate with every run, and nothing said how many there were, how much room they took,
  or what a person should do about them; a record whose agent had been removed vanished
  from the screen but stayed on disk. The Runs note area now draws `N run records on disk,
  <size> in total.`, then, when some belong to an agent the configuration no longer lists,
  how many and that they stay on disk until they are deleted, then `To free their space,
  remove a run's directory under that path. The product only reads run records; it never
  deletes one by itself.` The footprint counts every agent directory, configured or not, so
  a removed agent's history does not disappear from the count.
- **The files that grow with each run show their size.** The Agent screen's `newest log`
  reads its size beside the path and gains a `transcript` field with its own size, and the
  Runs note repeats both sizes beside their paths, so the files a run appends to are
  visibly growing instead of being a bare path.
- **The risk acknowledgment is visible to a second person.** On a configuration directory
  that already holds a recorded acknowledgment, the hub's note area now names when it was
  given and the version the record itself carries, and `R` reads the terms again
  **read-only**, so reading them does not rewrite the record. A second person on a used
  machine can see what someone else agreed to, before anything starts.
- **The identity sentence and the failure class are whole words.** The Forgejo identity
  line now finishes — `not settled — press i for \`gewu-scribe\`; v supplies the token` —
  rather than stopping at `… the token is from v`. The hub's state column shortens every
  failure class to a word that fits whole (`failed (server)`, `failed (key)`), never an
  ellipsised fragment such as `failed (s…er_error)`; the Agent screen keeps the long form
  (`failed (server_error)`) where the column is wide enough.
- **A leftover secret carries an age.** A credential left behind by an agent that is no
  longer configured now reads with the age of the file that holds it
  (`left by a credentials file last written 3 days ago`), so a stale secret can be told
  from one just written.

## What it needs

- A 64-bit **x86_64** Linux machine with **glibc 2.39 or newer** — Ubuntu 24.04 or newer,
  Debian 13 or newer, Fedora 40 or newer, or any distribution that new. The binary is
  dynamically linked against your system's glibc; it is not a static build. The floor was
  read from the ELF (`.gnu.version_r` names `GLIBC_2.39`), not assumed.
- A **terminal**. The UI needs a terminal on standard input and standard output; started
  without one it stops with a sentence rather than a panic.
- **Your own `git`**, when you ask an agent to work on a repository.
- At **first run**, nothing beyond the above: the tool writes a commented `config.toml`
  and a `credentials.toml` (mode 0600) under `~/.config/gewu-multiverse`, and asks you
  once to acknowledge that a run acts with your rights and is not a sandbox. Press `y`
  to record it, or `n` to leave it; a start stays refused until it is recorded. On a
  directory where it was already recorded, the hub names when and under which version,
  and `R` reads the terms again without changing the record.

## What it deliberately does not do yet

- **No build for other machines.** This is x86_64 Linux only: there is no aarch64 build,
  no musl/static build, and no macOS or Windows build. On a machine with an older glibc
  than 2.39, use the source install instead.
- **No package format.** The release is a tarball, a checksum and this note: there is no
  `.deb`, no `.rpm`, no container image. The repository's `install.sh` performs the
  download, checksum and install in one line.
- **No service.** The terminal UI is the interface. An agent can be put under your own
  user systemd from the UI — that is documented — but nothing is installed as a service.
- **No sandbox.** An agent runs as you. That is a layout, not a security boundary, and
  the README says so at length.
- **The product never deletes a run record.** Run records and their logs and transcripts
  accumulate; the Runs screen now says how many there are, how much room they take, and
  that freeing the space is a person removing a run's directory. Automatic pruning is
  deliberately not done.
- **The crate version string is `0.1.13`, and it matches the tag.** `Cargo.toml` and the
  committed `Cargo.lock` both carry it, so `gewu-multiverse --version` reports the version
  the release is named for, and `cargo build --locked` means something on a fresh clone.

## How it was built

`cargo build --release --locked` on x86_64 Linux, with rustc 1.98.1 and cargo 1.98.1,
target `x86_64-unknown-linux-gnu`, at revision
`9b54dfbd719e3190a925a9343f18faae3766f1b4` (the version commit on the release branch).
The repository commits its `Cargo.lock`, so the build held `--locked` against the
committed lock. The tarball also holds the README and both licence files.
