# gewu-multiverse v0.1.2 — the second fix round

This is the third prebuilt release of `gewu-multiverse`. It is built from `main`
after the second round of interface fixes, and packed so you can try it without a
Rust toolchain. Nothing about the install or the design changed: if `v0.1.1` ran on
your machine, this one runs there too. It is also the release whose binary reports
the version it is named for: `gewu-multiverse --version` prints `0.1.2`.

## What it is

`gewu-multiverse` is a local, single-Universe Matrixverse — one small terminal
application that turns a Linux machine into a place where you run **agents against
your own Forgejo**, with no server, no accounts and no cloud. You install it, open
the terminal UI, point it at one Forgejo, and define each agent with its own model
endpoint, key and instructions. Agents run as children of the UI by default, or as
user units that outlive the window when you ask for that; every run leaves a log and
an append-only JSONL transcript. The README describes all of it, and the
[quickstart](https://github.com/Callo42/gewu-multiverse#quickstart-from-nothing-to-a-running-agent)
walks from install to a run's log.

## What changed since v0.1.1

The first fix round made the product kind to a person opening it for the first
time. This round fixes what running it revealed: a run that outlived a killed
window, secrets and removal that still meant editing a file, and a set of smaller
interface wrongs. Each of these has a test behind it.

- **A killed window no longer leaves a run behind.** Each run asks the kernel to
  end when the window that started it ends, so a window killed outright takes the
  runs it started with it. A window opened afterwards closes a run that was left
  behind as `stopped`, with the reason it gives, instead of calling the agent
  `idle` and letting a second run start in the same workspace.
- **A secret you need later is supplied in the product, masked.** `k` sets an
  agent's model key and `f` the Forgejo role token on the Credentials screen; `v`
  sets an agent's own Forgejo token and `A` the administrator token on the Forgejo
  screen. Each is one field, drawn as `*` and written straight to the credentials
  file; the value is never echoed, never put in a status line and never drawn on a
  screen.
- **The add-agent form refuses an agent it cannot finish.** The model key is now
  required, so the form cannot create an agent whose next step is to edit a file.
- **An agent can be removed in the product.** `d` asks first, names the files the
  agent leaves on disk, and `y` removes it from `config.toml`; `n` keeps it. A
  mistyped agent is no longer a dead end that ends in a text editor.
- **A window too small to be honest says so.** Below 72×18 the product shows one
  line naming the size it needs, instead of clipping panels, the action line and
  paths in silence.
- **The instruction template's guidance is never sent as instruction.** The file a
  new agent gets carries one marked placeholder line; the line is dropped before a
  run sends the document to the model.
- **A failed run carries its reason to the screen you are looking at.** The state
  cell names the failure class (`failed (transport)`), and the run's own reason is
  kept on the agent and shown on its screen, not only in a footer line.
- **The smaller wrongs, each with a test.** A failed administrator check keeps the
  last good role view and shows the failure beside it; the chosen repository carries
  a `>` in text and not only in colour; `^C` leaves the UI instead of running the
  role check; the key legend is fitted to the width and ends with `? all keys`; a
  press that cannot act says so; a very long invalid name leads with the reason
  rather than burying it; `concurrency` and `max turns` are defined where they
  appear; a credentials file that cannot be read is not reported as empty; and the
  Agents screen defines `agent`, `concurrency`, `max turns` and the two supervision
  modes where they first appear.

## What it needs

- A 64-bit **x86_64** Linux machine with **glibc 2.39 or newer** — Ubuntu 24.04 or newer,
  Debian 13 or newer, Fedora 40 or newer, or any distribution that new. The binary is
  dynamically linked against your system's glibc; it is not a static build. The floor was
  read from the ELF (`.gnu.version_r` names `GLIBC_2.39`), not assumed.
- A **terminal**. The UI needs a terminal on standard input and standard output; started
  without one it stops with a sentence rather than a panic.
- **Your own `git`**, when you ask an agent to work on a repository.
- At **first run**, nothing beyond the above: the tool writes a commented `config.toml`
  and a `credentials.toml` (mode 0600) under `~/.config/gewu-multiverse`, and asks you
  once to acknowledge that a run acts with your rights and is not a sandbox. Press `y`
  to record it, or `n` to leave it; a start stays refused until it is recorded.

## What it deliberately does not do yet

- **No build for other machines.** This is x86_64 Linux only: there is no aarch64 build,
  no musl/static build, and no macOS or Windows build. On a machine with an older glibc
  than 2.39, use the source install instead.
- **No package format.** The release is a tarball, a checksum and this note: there is no
  `.deb`, no `.rpm`, no container image. The repository's `install.sh` performs the
  download, checksum and install in one line.
- **No service.** The terminal UI is the interface. An agent can be put under your own
  user systemd from the UI — that is documented — but nothing is installed as a service.
- **No sandbox.** An agent runs as you. That is a layout, not a security boundary, and
  the README says so at length.
- **The crate version string is `0.1.2`, and it matches the tag.** `Cargo.toml` and the
  committed `Cargo.lock` both carry it, so `gewu-multiverse --version` reports the version
  the release is named for, and `cargo build --locked` means something on a fresh clone.

## How it was built

`cargo build --release --locked` on x86_64 Linux, with rustc 1.98.1 and cargo 1.98.1,
target `x86_64-unknown-linux-gnu`, at revision
`67f042f136f14012b287eb820388b86900d27841`. The repository commits its `Cargo.lock`,
so the build held `--locked` against the committed lock. The tarball also holds the
README and both licence files.
