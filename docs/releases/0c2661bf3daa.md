# gewu-multiverse v0.1.4 — the fourth fix round

This is the fifth prebuilt release of `gewu-multiverse`. It is built from `main`
after the fourth round of interface fixes, and packed so you can try it without a
Rust toolchain. Nothing about the install or the design changed: if `v0.1.3` ran on
your machine, this one runs there too. The binary reports the version it is named
for: `gewu-multiverse --version` prints `0.1.4`.

## What it is

`gewu-multiverse` is a local, single-Universe Matrixverse — one small terminal
application that turns a Linux machine into a place where you run **agents against
your own Forgejo**, with no server, no accounts and no cloud. You install it, open
the terminal UI, point it at one Forgejo, and define each agent with its own model
endpoint, key and instructions. Agents run as children of the UI by default, or as
user units that outlive the window when you ask for that; every run leaves a log and
an append-only JSONL transcript. The README describes all of it, and the
[quickstart](https://github.com/Callo42/gewu-multiverse#quickstart-from-nothing-to-a-running-agent)
walks from install to a run's log.

## What changed since v0.1.2

If you are upgrading from `v0.1.2`, this build carries **two** rounds of fixes: the
third fix round, which `v0.1.3` published, and the fourth fix round, which is this
build. If you are already on `v0.1.3`, the new work is the fourth round, listed
first; the third round is summarised after it, so a `v0.1.2` reader loses nothing.

### The fourth fix round — new in this build

The third round fixed what *watching several agents over time* revealed. This round
fixes what *watching the same product under a paste, a closed window, and a Forgejo
list longer than its panel* revealed: a list that hid repositories, a removal that
could orphan a run, a quit that ended a run without a word, and a set of smaller
truths. Each of these has a test behind it.

- **The Forgejo repository list no longer hides a repository.** When more
  repositories can be reached than fit, the panel shows a window of rows titled
  `repositories a–b of N — ↓/↑ more`; the selected repository is always drawn and
  carries a `>` marker, so the selection never moves onto a row you cannot see.
- **Removing an agent while it runs is refused, with the run named.** `d` on an
  agent whose run is in flight (or still waiting for a slot) says so, names the run
  and offers `x`, exactly as the supervision switch already refuses. The agent stays
  configured and the run stays visible and stoppable, so a removal can never leave a
  run that nothing counts and nothing can stop. Removing an agent by hand and
  re-reading the configuration stops its run and names it, too.
- **Quitting with a run in flight warns once.** `q` names how many runs will stop
  and asks again; any other key stays. A run ended that way records that the UI was
  closed, not “on request”.
- **A second start speaks in the operator's voice.** Starting an agent that is
  already running leads with `is already running` and names `x`, instead of the
  ledger's wording.
- **The hub and the Runs ledger use one word for a finished run.** Success is
  `succeeded` in both places; the hub no longer says `exited 0` where the ledger says
  `succeeded`.
- **A bracketed paste into a one-line field keeps one line and replaces.** A
  multi-line paste keeps its first line and says the rest was unused; a second paste
  replaces the field instead of appending to it; a masked field shows how many
  characters it holds.
- **The add-agent form's action line is inside the panel at every size**, and the
  key-help overlay is a scrollable window titled `keys a–b of N — ↓/↑ more`, so
  `enter writes it` and every key survive an 80×24 terminal.
- **The Instruction screen shows the size on disk and the size a run sends**, and
  names the guidance line that is dropped, so the two sizes are not confused; only
  the product's own first guidance line is dropped, and a line of your own that
  matches it later is kept.
- **A failed clone names the account it acted as and the list's source**, before
  git's detail, so two different tokens are not confused.
- **Modals leave the footer's status rows visible**, so a sentence about what just
  happened — a refused submit, a paste note — is never cleared away by the overlay.
- **The smaller truths, each with a test.** The `started` column says it is UTC and
  keeps its `Z`; a run in flight records the model call it is waiting for before the
  call, so a wait is not a wedge; an abandoned run reports the time it actually ran,
  not `0.0s`; the first-run acknowledgment shows its whole record path at 80×24; and
  an administrator's token checked as `member` says so and names the key for the
  other view.

### The third fix round — carried from v0.1.3

For a `v0.1.2` reader, this build also contains everything `v0.1.3` published: the
agent list no longer hides an agent (a window titled `agents a–b of N — ↓/↑ more`,
the selected row always drawn and marked `>`); a restart seeds each agent from its
newest terminal record, so the hub shows the last outcome and reason rather than
`idle`; the footer carries `Running: N of M` on every screen and `· K finished` once
a run has ended since the window opened; a signalled stop reads `stopped … is proven
gone` once the record closes; the removal confirmation only promises files that
exist; the Forgejo screen shows the identity and its mode persistently; the Runs
note area leads with the reason; an interrupted editor's emergency save is named; a
credential belonging to a removed agent is marked as such; and one size below the
advertised minimum says the window is too small instead of clipping in silence.

## What it needs

- A 64-bit **x86_64** Linux machine with **glibc 2.39 or newer** — Ubuntu 24.04 or newer,
  Debian 13 or newer, Fedora 40 or newer, or any distribution that new. The binary is
  dynamically linked against your system's glibc; it is not a static build. The floor was
  read from the ELF (`.gnu.version_r` names `GLIBC_2.39`), not assumed.
- A **terminal**. The UI needs a terminal on standard input and standard output; started
  without one it stops with a sentence rather than a panic.
- **Your own `git`**, when you ask an agent to work on a repository.
- At **first run**, nothing beyond the above: the tool writes a commented `config.toml`
  and a `credentials.toml` (mode 0600) under `~/.config/gewu-multiverse`, and asks you
  once to acknowledge that a run acts with your rights and is not a sandbox. Press `y`
  to record it, or `n` to leave it; a start stays refused until it is recorded.

## What it deliberately does not do yet

- **No build for other machines.** This is x86_64 Linux only: there is no aarch64 build,
  no musl/static build, and no macOS or Windows build. On a machine with an older glibc
  than 2.39, use the source install instead.
- **No package format.** The release is a tarball, a checksum and this note: there is no
  `.deb`, no `.rpm`, no container image. The repository's `install.sh` performs the
  download, checksum and install in one line.
- **No service.** The terminal UI is the interface. An agent can be put under your own
  user systemd from the UI — that is documented — but nothing is installed as a service.
- **No sandbox.** An agent runs as you. That is a layout, not a security boundary, and
  the README says so at length.
- **The crate version string is `0.1.4`, and it matches the tag.** `Cargo.toml` and the
  committed `Cargo.lock` both carry it, so `gewu-multiverse --version` reports the version
  the release is named for, and `cargo build --locked` means something on a fresh clone.

## How it was built

`cargo build --release --locked` on x86_64 Linux, with rustc 1.98.1 and cargo 1.98.1,
target `x86_64-unknown-linux-gnu`, at revision
`0c2661bf3daac1ab4615e9c120d100074b14d677`. The repository commits its `Cargo.lock`,
so the build held `--locked` against the committed lock. The tarball also holds the
README and both licence files.
