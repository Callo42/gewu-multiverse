# gewu-multiverse v0.1.1 — the first fix round

This is the second prebuilt release of `gewu-multiverse`. It is the same program as
`v0.1.0`, built from `main` after the first round of interface fixes, and packed so you
can try it without a Rust toolchain. Nothing about the install or the design changed:
if `v0.1.0` ran on your machine, this one runs there too.

## What it is

`gewu-multiverse` is a local, single-Universe Matrixverse — one small terminal
application that turns a Linux machine into a place where you run **agents against your
own Forgejo**, with no server, no accounts and no cloud. You install it, open the
terminal UI, point it at one Forgejo, and define each agent with its own model endpoint,
key and instructions. Agents run as children of the UI by default, or as user units that
outlive the window when you ask for that; every run leaves a log and an append-only JSONL
transcript. The README describes all of it, and the
[quickstart](https://github.com/Callo42/gewu-multiverse#quickstart-from-nothing-to-a-running-agent)
walks from install to a run's log.

## What changed since v0.1.0

`v0.1.0` worked, but it was unkind to a person opening it for the first time. This
release is the first round of fixes for that, and each fix has a test behind it:

- **A page map, and screens built against it.** Every screen and every state a user can
  be in now has a written row saying what it shows and what it must offer — a missing
  next step, or a word the user has not been given, is a defect against that row. The
  map is in the repository as `docs/page-map.md`.
- **Add an agent without leaving the product.** With nothing configured, the Agents
  screen says so and offers the form by name: press `n` (or `a`, or `enter`) and fill in
  an agent name, its model endpoint and id, and the model key. The product writes
  `config.toml` and `credentials.toml` for you and lists the agent. The form masks the
  key as it is typed; no secret is ever echoed.
- **The transcript is reachable from Runs.** Press `6`, choose a run, then `T` to open
  its transcript (`o` opens the log). Both are named on the screen. `v0.1.0` showed runs
  but left the transcript to a file path in the README.
- **Keys are no longer silent, and `?` shows every one.** A clipped legend now ends at a
  key boundary with `? all keys`, and `?` (or `h`, or `F1`) opens a grouped reference
  with one line per key. A press that cannot act says why rather than doing nothing.
- **The first screen fits at eighty columns.** The first-run acknowledgment owns every
  row it covers, so the panel behind it no longer collides with its edges at 80×24, and
  the tests guard that.
- **Failure text is honest.** A start that cannot proceed names the reason and the key
  that fixes it, on the screen where the user is standing.

The other fix in this release is not visible on a screen:

- **Every secret in the credentials file is redacted, not only the model key.** A run
  redacts its own model key and, with it, every other secret the file holds — the Forgejo
  role token, the administrator token and every per-agent token and key — so a tool that
  printed the credentials file cannot carry any of them into a log or a transcript.

## What it needs

- A 64-bit **x86_64** Linux machine with **glibc 2.39 or newer** — Ubuntu 24.04 or newer,
  Debian 13 or newer, Fedora 40 or newer, or any distribution that new. The binary is
  dynamically linked against your system's glibc; it is not a static build. The floor was
  read from the ELF (`.gnu.version_r` names `GLIBC_2.39`), not assumed.
- A **terminal**. The UI needs a terminal on standard input and standard output; started
  without one it stops with a sentence rather than a panic.
- **Your own `git`**, when you ask an agent to work on a repository.
- At **first run**, nothing beyond the above: the tool writes a commented `config.toml`
  and a `credentials.toml` (mode 0600) under `~/.config/gewu-multiverse`, and asks you
  once to acknowledge that a run acts with your rights and is not a sandbox. Press `y`
  to record it, or `n` to leave it; a start stays refused until it is recorded.

## What it deliberately does not do yet

- **No build for other machines.** This is x86_64 Linux only: there is no aarch64 build,
  no musl/static build, and no macOS or Windows build. On a machine with an older glibc
  than 2.39, use the source install instead.
- **No package format.** The release is a tarball, a checksum and this note: there is no
  `.deb`, no `.rpm`, no container image. The repository's `install.sh` performs the
  download, checksum and install in one line.
- **No service.** The terminal UI is the interface. An agent can be put under your own
  user systemd from the UI — that is documented — but nothing is installed as a service.
- **No sandbox.** An agent runs as you. That is a layout, not a security boundary, and
  the README says so at length.
- **The crate version string is unchanged.** `gewu-multiverse --version` still prints
  `0.1.1`, matching the release tag: the crate version and the committed lock file were added with this
  release, so `--locked` means something on a fresh clone.

## How it was built

`cargo build --release --locked` on x86_64 Linux, with rustc 1.98.1 and cargo 1.98.1,
target `x86_64-unknown-linux-gnu`, at revision
`7374c4d83bf2e9405a0b70e34b2aa56cd26561af`, with the version-and-lock commit
`7849e74307b6e705a479fd61403fb7326b1cd3f3` on top — the release tag points there. The repository now commits its
`Cargo.lock`, so the build holds `--locked` against the committed lock.
The tarball also holds the README and both licence files.
