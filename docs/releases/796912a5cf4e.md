# gewu-multiverse v0.1.6 — the sixth fix round

This is the seventh prebuilt release of `gewu-multiverse`. It is built from `main`
after the sixth round of interface fixes, and packed so you can try it without a
Rust toolchain. Nothing about the install or the design changed: if `v0.1.5` ran on
your machine, this one runs there too. The binary reports the version it is named
for: `gewu-multiverse --version` prints `0.1.6`.

## What it is

`gewu-multiverse` is a local, single-Universe Matrixverse — one small terminal
application that turns a Linux machine into a place where you run **agents against
your own Forgejo**, with no server, no accounts and no cloud. You install it, open
the terminal UI, point it at one Forgejo, and define each agent with its own model
endpoint, key and instructions. Agents run as children of the UI by default, or as
user units that outlive the window when you ask for that; every run leaves a log and
an append-only JSONL transcript. The README describes all of it, and the
[quickstart](https://github.com/Callo42/gewu-multiverse#quickstart-from-nothing-to-a-running-agent)
walks from install to a run's log.

## What changed since v0.1.2

If you are upgrading from `v0.1.2`, this build carries **four** rounds of fixes: the
third fix round, which `v0.1.3` published; the fourth, which `v0.1.4` published; the
fifth, which `v0.1.5` published; and the sixth fix round, which is this build. If you
are already on `v0.1.5`, the new work is the sixth round, listed first; the earlier
rounds are summarised after it, so a `v0.1.2` reader loses nothing.

### The sixth fix round — new in this build

The fifth round fixed what *watching someone leave a mode, read a cause that had been
cut off, and trust a screen that was not telling the truth* revealed. This round fixed
what *watching someone meet a server that went away, shrink the window, and try to
leave a text view* revealed. Each fix has a test behind it, and the classes were
swept: every path of a fixed class is listed as fixed, already correct, or open with a
reason.

- **Nothing truncates in silence.** The rule that a panel declares what it cannot draw
  is now the class rule, not one screen's. Every bordered panel — Agent, Instruction,
  Credentials, Forgejo and the Runs notes — puts `more below; enlarge the window` in its
  title (the one line that is always drawn) when its wrapped content exceeds the window,
  and the two borderless note areas (Agents and Runs) reserve their last drawn row for
  the same sentence. At the advertised minimum size, each screen's own must-offer
  sentence is drawn by ordering it above prose that can wait: the Instruction screen's
  *what a run sends*, and the Credentials screen's `k`/`f`/`A` keys, are on screen at
  80×24 rather than falling off it. The add-agent form windows its body so the field the
  cursor is on is always drawn, and its title carries the same declaration.
- **The hub answers for the last run, not the last failure.** After a network outage
  ended and a later run succeeded, the hub still said the last run *did not go well*,
  because it searched for the newest **failed** record. It now reads the agent's newest
  terminal record: a failure only when that newest record is the failure. The Agent
  screen keeps the historical `last failure`, so an older failure is still visible as
  history and never confused with what just happened.
- **A transport failure is on screen, in the product's own words.** The endpoint test's
  footer used to repeat only the class, with the cause below the fold; it now carries
  class **and** cause whole, grown by the footer. Every screen that shows a reason —
  the endpoint test, the hub and Runs note areas, the Agent screen's `last failure`, and
  each Forgejo failure — translates the transport's common failures into the product's
  words (`the endpoint refused the connection`, `the connection dropped`, `the address
  could not be resolved`) instead of the library's `io:` / `os error N`. The run's own
  log and transcript keep the transport's exact sentence, so the failure is still
  auditable afterwards.
- **The editor and pager hand-offs name the way out.** Before opening your editor with
  no `$EDITOR` set, the confirmation gave nano's keys but not how to leave it; it now
  says `In nano: ^X leaves; press Y and enter to save, or N to leave without saving.`
  (vi already named `:wq` / `:q!`). The Runs note and the status before `o`/`T` open the
  pager now name its own key: `Both open in your $PAGER; leave the pager with q.`
- **The smaller truths.** The removal confirmation names `enter` and `esc` as well as
  `y`/`n`; a run id too long for its column is ellipsised rather than cut mid-token;
  `esc agents` is among the keys the 80×24 legend draws; `^C` with a run in flight asks
  the same question `q` asks and leaves on a second `^C`; counts in plain-text lines
  read as sentences (`1 turn`, `2 turns`, `0 repositories`) instead of a `turn(s)`
  gutter, while the transcript keeps its numbers; PageDown/PageUp, Home/`g` and End/`G`
  move the selection on every list and page the key help, and a help key that cannot act
  says so; the tab bar carries each screen's number beside its name; `g`, `P` and `U`
  act only on the Forgejo screen (elsewhere `g` is the list's top); the instruction
  difference gets its own line so no sentence is broken after its negation; and a
  `systemd` record with no run yet reports an unreachable user manager instead of
  `idle`.

### The fifth fix round — carried from v0.1.5

Switching supervision is never a one-way door: `m` asks the machine first whether a user
unit can exist there, refuses before writing anything when no manager is reachable, and
leaving `systemd` needs no manager when no unit is on disk. A failed clone's own `fatal:`
cause is no longer clipped: the footer status grows to hold whatever it carries. The
Instruction screen names the real difference (a dropped guidance line, or just an
untrailed newline). The Credentials screen shows the mode the file actually has, read
each frame. A missing endpoint path is named rather than the model blamed. Starts, stops
and re-reads leave honest records. And a panel that hid fields says so.

### The fourth fix round — carried from v0.1.4

The Forgejo repository list no longer hides a repository (a window titled
`repositories a–b of N — ↓/↑ more`, the selected row always drawn and marked `>`);
removing an agent while it runs is refused with the run named; quitting with a run in
flight warns once and records that the UI was closed; a second start speaks in the
operator's voice; the hub and the Runs ledger use one word for success; a bracketed
paste into a one-line field keeps one line; the add-agent form's action line stays
inside the panel and the key help is a scrollable window; a failed clone names the
account it acted as and the list's source before git's detail; modals leave the footer's
status rows visible; and the smaller truths each carry a test.

### The third fix round — carried from v0.1.3

The agent list no longer hides an agent (a window titled `agents a–b of N — ↓/↑ more`,
the selected row always drawn and marked `>`); a restart seeds each agent from its
newest terminal record, so the hub shows the last outcome and reason rather than
`idle`; the footer carries `Running: N of M` on every screen and `· K finished` once a
run has ended since the window opened; a signalled stop reads `stopped … is proven
gone` once the record closes; the removal confirmation only promises files that exist;
the Forgejo screen shows the identity and its mode persistently; the Runs note area
leads with the reason; an interrupted editor's emergency save is named; a credential
belonging to a removed agent is marked as such; and one size below the advertised
minimum says the window is too small instead of clipping in silence.

## What it needs

- A 64-bit **x86_64** Linux machine with **glibc 2.39 or newer** — Ubuntu 24.04 or newer,
  Debian 13 or newer, Fedora 40 or newer, or any distribution that new. The binary is
  dynamically linked against your system's glibc; it is not a static build. The floor was
  read from the ELF (`.gnu.version_r` names `GLIBC_2.39`), not assumed.
- A **terminal**. The UI needs a terminal on standard input and standard output; started
  without one it stops with a sentence rather than a panic.
- **Your own `git`**, when you ask an agent to work on a repository.
- At **first run**, nothing beyond the above: the tool writes a commented `config.toml`
  and a `credentials.toml` (mode 0600) under `~/.config/gewu-multiverse`, and asks you
  once to acknowledge that a run acts with your rights and is not a sandbox. Press `y`
  to record it, or `n` to leave it; a start stays refused until it is recorded.

## What it deliberately does not do yet

- **No build for other machines.** This is x86_64 Linux only: there is no aarch64 build,
  no musl/static build, and no macOS or Windows build. On a machine with an older glibc
  than 2.39, use the source install instead.
- **No package format.** The release is a tarball, a checksum and this note: there is no
  `.deb`, no `.rpm`, no container image. The repository's `install.sh` performs the
  download, checksum and install in one line.
- **No service.** The terminal UI is the interface. An agent can be put under your own
  user systemd from the UI — that is documented — but nothing is installed as a service.
- **No sandbox.** An agent runs as you. That is a layout, not a security boundary, and
  the README says so at length.
- **The crate version string is `0.1.6`, and it matches the tag.** `Cargo.toml` and the
  committed `Cargo.lock` both carry it, so `gewu-multiverse --version` reports the version
  the release is named for, and `cargo build --locked` means something on a fresh clone.

## How it was built

`cargo build --release --locked` on x86_64 Linux, with rustc 1.98.1 and cargo 1.98.1,
target `x86_64-unknown-linux-gnu`, at revision
`796912a5cf4ed62bbc0a49e6681a0388eb9480ab` (the version commit on the release branch).
The repository commits its `Cargo.lock`, so the build held `--locked` against the
committed lock. The tarball also holds the README and both licence files.
